# 当班处置

收到新一批清运点单时先运行 `validate`。有隔离记录时对照 `reasons` 回查来源单号，再通过 `preview` 确认是否仍能覆盖当班。

## 先重算再发布

1. 先看 `/api/replay` 的保留样本与基线证据。高风险与证据不足的对象会分别进入派工和人工队列。`bands` 列出每个片区对共用误差带的可用性判定；`trusted=false` 的片区点位会直接转人工。
2. 按本班车载百公斤调低预算或增加预留。查看每个片区的已用数量及待分派原因，核对保护资源。缺可信误差带的片区不占车载额度，其额度留给仍能排车的片区。
3. 确认派工窗口后发布。相同预览再次提交会返回原版，旧版请求遇到其他派工已发布时须重算。
4. 从 `/api/ledger` 查询版号，按摘要获取完整快照或下载 CSV 与现场票据复核。

本班主要动作是「预留清运车」。未称重时按可信上界占载，超过单车承载的点位拆回调度分批清运。
数据含模拟异常，缺少可见证据、可信误差带或排班资源时如实返回等待或转人工。
